# Perfumance
> 사주 오행과 향수 취향을 결합한 개인화 향수 추천 서비스

Live Demo: https://perfumance-kappa.vercel.app

---

## 1. 프로젝트 소개

**Perfumance**는 행동 이력이 없는 신규 사용자의 초기 추천 문제를 보완하기 위해 고안된 하이브리드 추천 서비스입니다. 
사용자의 생년월일시 정보로부터 도출된 **사주 오행(목·화·토·금·수)의 밸런스**를 분석하여 부족한 기운을 보완하고, 사용자가 입력한 **선호 및 비선호 향조**를 결합한 점수화 알고리즘을 사용합니다. 이를 통해 행동 이력이 없는 신규 사용자에게도 추천 근거를 제공하는 초기 추천을 제공합니다.

* **BALANCED 추천 정책 도입**: 유명 브랜드 가점에 따른 편향을 완화하고 사용자 선호 향조의 반영 비중을 높였습니다.

## 4. 문제와 해결 방식

1. **사용자 행동 데이터 부재 (Cold Start)**
   * **해결**: 구매나 클릭 이력 없이도 고유하게 추출되는 사주(오행 균형론) 데이터와 첫 진입 시 선택한 최소한의 향조 선호 정보를 활용하여 초기 추천을 제공합니다.
2. **블랙박스 추천으로 인한 설득력 부재**
   * **해결**: 추천된 향수의 노트 정보와 오행의 부족한 기운이 조화를 이루는 이유를 사주 해설과 함께 오행 밸런스 시각화 및 AI 생성 맞춤 해설로 풀어서 제공합니다.
3. **인프라 결합 및 API 의존성 리스크**
   * **해결**: AI 생성 단계를 격리하고, 외부 API 장애나 대기시간이 발생하더라도 핵심 규칙 기반 추천 결과를 안전하게 출력하도록 오프라인 템플릿 기반 Fallback 구조를 설계했습니다.

## 8. 추천 알고리즘

최종 추천 점수는 사주와 취향 가중치를 고르게 반영하는 **BALANCED 정책**을 기본으로 사용합니다.

### 1) 점수 연산 수식
$$\text{final\_score} = 0.40 \times \text{sim} + 0.20 \times \text{weak\_fill\_avg} + 0.35 \times \text{preference} - 0.35 \times \text{dislike} + \text{brand\_bonus}$$

* **sim (사주 오행 유사도)**: 사용자 사주 목표 벡터(부족 오행=1.0, 강한 오행=0.1, 일반=0.5)와 향수의 오행 분포 벡터 간의 코사인 유사도.
* **weak_fill_avg (부족 오행 보완 평균)**: 부족한 오행 속성들이 향수 노트에 채워져 있는 평균 비율.
* **preference (선호 가점)**: 사용자가 좋아하는 향조 키워드가 매칭될 시 점수 부여.
* **dislike (비선호 감점)**: 피하고 싶은 향조 매칭 시 감산 적용. 
  * *비선호 특수 규칙*: `dislike_score >= 0.4`인 경우, 하드 필터(목록 배제)가 아닌 **강한 감점 정책**을 적용하여 최종 점수에 추가로 `-0.40`의 추가 감점을 부여함으로써 자연스럽게 후순위로 배제되도록 유도합니다.
* **brand_bonus (브랜드 보너스)**: 인지도가 높은 유명 브랜드 향수일 때 최종 점수에 `+0.03` 가산 적용.

### 2) BASELINE 가중치 설정 (비교군)
* `sim_weight` (사주 유사도): **0.55**
* `weak_fill_weight` (부족 오행 보완): **0.20**
* `preference_weight` (선호 가점): **0.18**
* `dislike_weight` (비선호 감점): **-0.20** (비선호 `>= 0.4` 시 최종 점수에 `-0.50` 추가 감점 적용)
* `brand_bonus` (브랜드 보너스): 최종 점수에 **+0.15** 가산

### 3) 오행 동률 처리
* **strongest_elements**, **weakest_elements**를 배열 형태로 지원하여, 사주 상 오행 분포 점수가 완벽히 같은 동률 오행이 나타났을 때 임의로 하나만 선택하지 않고 배열 전체를 밸런싱 타겟으로 보존합니다.
* 부족 오행이 여러 개일 경우, 향수 오행 점수 평균(`weak_fill_avg`)을 사용해 점수를 조율합니다.
* 기존 `strongest`, `weakest` 단일 텍스트 필드는 레거시 클라이언트 호환용으로 유지합니다.

## 10. 데이터 정제

Pandas 기반 정제 스크립트(`scripts/run_data_cleaning.py`)를 통해 마스터 DB를 가공했습니다.

1. **데이터 수치**: 정제 전 **4,298개** ➡️ 정제 후 **4,292개** 레코드 유지.
2. **중복 레코드 제거**: 브랜드명과 제품명이 완벽히 일치하는 단순 중복 데이터 6개를 안전하게 병합 제거했습니다.
3. **브랜드 표기 정규화**: 대소문자 표기 및 하이픈 유무로 나뉘어 있던 브랜드 표기 불일치 360건 정규화.
4. **텍스트 정제**: 웹 파싱 문구 혼입 및 인코딩이 깨진 오염 데이터 54건 자동 정제.
5. **독립 제품 보존**: 농도나 규격 표기상 동일 제품으로 판정된 표기 중복만 제거하였으며, 향조 구성이 실질적으로 다른 EDT, EDP, Parfum 변형 등은 별도 제품으로 유지했습니다.
   * *보존 예시*: `Black Orchid` / `Black Orchid Parfum`, `Noir Extreme` / `Noir Extreme Parfum`, `Eros` / `Eros Parfum`, `Do Son Eau de Toilette` / `Do Son Eau de Parfum`
6. **수동 검토 격리**: 향조 정보가 완전 결측 상태이거나 식별이 불분명한 27건은 자동 병합에서 제외하고 수동 검토(`fatescent_master_db_v2_manual_review.csv`) 대상으로 보관.
7. **성별 필터**: 데이터 상 성별 정보가 비어 있는 2,217개의 `unknown` 레코드는 unisex 등으로 임의 추정하지 않고 데이터의 한계로 남겨두었으며, 백엔드의 중립 점수 및 후보 fallback 정책에서 안전하게 처리하도록 설계하였습니다. 또한, 백엔드와 프론트엔드 간 성별 매핑 값 불일치(남성/남성향/male 등)를 male, female, unisex 규격으로 표준화하였습니다.

## 11. Gemini와 fallback

### 1) Structured Output 장문 JSON 잘림 문제 대응
* **문제**: Google GenAI SDK를 통해 Gemini 모델에 엄격한 Schema 형태의 Response JSON 출력을 요구하였을 때, 장문의 사주 풀이를 생성하는 과정에서 최대 출력 토큰 한계 또는 문장 중단으로 인해 JSON 끝단 괄호가 잘려나가는 **JSON 파싱 오류**가 발생하여 화면이 강제 종료되는 문제가 있었습니다.
* **해결**: 스키마 제약 대신 일반 JSON 출력 모드로 변경하여 충분한 여유 토큰 버퍼를 제공하도록 유도하고, 받아온 로우 데이터를 파싱하여 백엔드에서 **Pydantic 사후 유효성 검증(Schema Validation)** 과정을 거치도록 코드를 재설계했습니다. 데이터 누락 또는 스키마 포맷 오류 발생 시 깨진 JSON을 억지로 노출하지 않고 폐기 처리합니다.

### 2) 안정적인 Fallback 아키텍처
* **API Key 누락**: 환경변수가 설정되지 않은 경우 Gemini API 호출을 사전에 생략하고 즉시 규칙 기반 대체 응답을 반환합니다.
* **네트워크 지연**: API 통신 시 30초 타임아웃(`asyncio.wait_for(..., timeout=30.0)`) 임계값을 설정하여 그 이상 지체될 시 규칙 기반 대체 응답을 반환합니다.
* **오류 발생**: 429(할당량 초과), 500(서버 내부 오류), JSON 파싱 오류 등 예외 발생 상황에서도 로컬 템플릿 기반으로 AI 장애 상황에도 핵심 추천 결과를 안전하게 유지합니다.

## 12. 테스트 및 안정화

지속적인 배포 환경에서의 안정성을 확보하기 위해 **72개의 유닛 및 통합 자동 테스트 스위트**를 운영하고 있습니다.

* **실행 명령**:
  ```bash
  python -m pytest -q --asyncio-mode=auto
  ```
* **구축 내용**:
  * 외부 실시간 API 연동 및 로컬 포트가 켜져 있어야 하는 호스트 의존적 테스트들을 제거하고, Mocking 기반의 오프라인 단위 테스트로 구조를 전환했습니다.
  * 윤년 경계치 입력 및 출생시간 결측 보정 규칙 테스트(30개)
  * 향조 오탐(단어 경계 및 토큰 분리 비교) 방지 테스트(12개)
  * 추천 정책 시나리오 검증(26개)
  * Gemini API 에러 모킹 상황 시 Fallback 전환 통합 테스트(4개)
* **결과**: **72 passed, 0 failed**
